### 1.3 工具流水线（ToolExecutor 五关）

`ToolExecutor.execute_calls(tool_calls, messages)` 返回 `(all_calls, all_results)`，内部逐工具过五关：

```
① 限流 check     core/rate_limit.py   频率窗口内最多 N 次
② 需确认?        tools/safety.py      危险工具挂起，等 confirm_pending()
③ 安全校验       tools/safety.py      危险命令模式/路径受限/参数范围
④ 执行           同步 or 异步(async_executor)  耗时工具后台跑
⑤ 审计            tools/audit.py      写 JSONL，超10MB轮转
```

证据：[core/tool_executor.py](file:///e:/Projects0/Agent/ZiJin/core/tool_executor.py#L49-L121)

### 🔧 扩展点 1：添加新工具（最高频）

**位置**：`tools/` 目录 + [tools/__init__.py](file:///e:/Projects0/Agent/ZiJin/tools/__init__.py) 的 import 列表

**步骤**（3 步完成注册到生效）：

```python
# 1. tools/my_tool.py - 新建工具文件
from tools.registry import registry

@registry.register(
    name="get_weather",                # LLM 看到的工具名
    description="查询指定城市的天气",   # LLM 决定何时调用的依据，描述要写清楚
    parameters={
        "type": "object",
        "properties": {
            "city": {"type": "string", "description": "城市名"},
        },
        "required": ["city"],
    },
    safety_level="safe",               # safe / moderate / dangerous
    required_confirm=False,            # True 则执行前需用户确认
)
def get_weather(city: str) -> str:
    """函数即工具实现，返回的字符串会作为结果喂回 LLM"""
    return f"{city} 今天晴，25℃"
```

```python
# 2. tools/__init__.py - 追加 import，保证模块被加载注册
import tools.my_tool
```

```python
# 3. 验证 - 启动日志应出现新工具名
#    main.py 启动时打印: 已注册工具: [..., 'get_weather', ...]
```

**可扩展的关联点**：若工具需要**异步**（慢操作），把工具名加入 [tool_executor.py#L72](file:///e:/Projects0/Agent/ZiJin/core/tool_executor.py#L72) 的 `async_tools` 集合；若需**限流**，在 [rate_limit.py#L8-L15](file:///e:/Projects0/Agent/ZiJin/core/rate_limit.py#L8-L15) 的 `DEFAULT_LIMITS` 加规则；若需**安全校验**，在 [safety.py](file:///e:/Projects0/Agent/ZiJin/tools/safety.py#L27-L54) 的 `validate_tool_input` 中加分支。

### 🔧 扩展点 3：订阅事件总线（跨模块联动）

任何模块都能 `bus.on()` 监听，实现解耦联动。现有案例：TTS 播放 → Live2D 口型同步（[tts.py#L27-L36](file:///e:/Projects0/Agent/ZiJin/tools/tts.py#L27-L36) 发射、[main_window.py#L105-L106](file:///e:/Projects0/Agent/ZiJin/ui/main_window.py#L105-L106) 订阅）。

# 例如：每次 Agent 回复时弹系统通知

    print(f"[通知] {emotion}: {text}")

bus.on("agent_reply", on_reply)   # 注意：此事件当前未发射，需在 agent._make_reply 中 emit

> ⚠️ 注意：`agent_reply` 事件在 [agent.py](file:///e:/Projects0/Agent/ZiJin/core/agent.py) 中**目前未发射**（docs/api.md 有记录但代码未实现），若需使用请在 `_make_reply`/`chat_stream` 结束时自行 `bus.emit("agent_reply", ...)`。

## 5. 给二次开发者的三条忠告

1. **先改 `SYSTEM_PROMPT` 与 `build_emotion_prompt()`，再改代码**：人设、工具使用规则、回复格式全部由提示词驱动（[settings.py#L85-L128](file:///e:/Projects0/Agent/ZiJin/config/settings.py#L85-L128)、[emotion.py#L85-L115](file:///e:/Projects0/Agent/ZiJin/core/emotion.py#L85-L115)）。改了输出格式，必须同步改 `extract_emotion` 解析。
2. **工具描述写得越好，LLM 用工具越准**：`description` 决定 function calling 命中率，是工具系统的核心调优点。
3. **core 层保持零 UI 依赖**：新增逻辑放 `core/`，界面展示用事件总线或返回值传递，别让 UI 类 import 进 core。
